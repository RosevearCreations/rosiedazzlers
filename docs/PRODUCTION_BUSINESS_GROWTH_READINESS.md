# Build 395 — Production Business Acceptance & Growth Readiness

## Purpose

Build 395 closes the current forward roadmap with a whole-platform, observation-only acceptance authority. It does not add a second business ledger or fabricate live demand. It composes the retained software authorities required to safely support growth and verifies that Production is the exact protected-main source that passed those authorities.

## Whole-platform acceptance matrix

- **Anonymous acquisition:** one meaningful H1, unique metadata/canonical/structured data, truthful local/service discovery and current public navigation.
- **Commercial/service discovery:** current package and add-on rules, realistic inspection-dependent scope, pricing/escalation language and genuine local/service proof.
- **Condition-aware booking:** responsive booking, current availability/pricing, condition-based estimate escalation, customer approval and recovery boundaries.
- **Customer/account:** authenticated customer/vehicle identity and retained account/service-history isolation.
- **Field execution:** staff permissions, mobile job readiness, completion evidence and permitted actions only.
- **Proof/media:** consent-aware before/after/publication evidence, assignment provenance, R2 synchronization reliability and no synthetic proof.
- **Payment/finance:** genuine provider evidence, final-balance readiness, reconciliation, recorded provider fees, HST, month-end and accountant-export readiness.
- **Retention/maintenance/fleet:** genuine rebook eligibility, maintenance activation and fleet authorities using current capacity/business rules.
- **Operations/inventory/job-cost:** canonical movement/reversal, depletion, reorder/substitution provenance and recorded material-cost evidence without a second inventory ledger.
- **Admin/I.T.:** release control, readiness diagnostics and operator-facing fail-closed status.
- **I.T. diagnostics and observability:** Production observability/self-diagnostics remain retained authority; missing live evidence is never converted to success.
- **Performance, accessibility, security and recovery:** retained hardening, rollback/recovery and repository-hygiene authorities remain part of Production readiness.

## Exact release evidence

Feature acceptance requires the focused Build 395 authority, Current Source Gate and feature-preview proof. Development must then prove the identical accepted SHA through its source and Cloudflare Development runtime authority. Production promotion must use protected `main` through the active pull-request ruleset.

After merge, the resulting `main` head is the **exact Production SHA**. Production GREEN is fail-closed until that exact SHA is observed as a successful Cloudflare Production deployment with Functions enabled and passes immutable plus canonical runtime smoke together with the retained business-path authority.

## Evidence boundaries

No real-world evidence is synthesized. Source tests and release automation do not create customers, bookings, charges, refunds, PayPal/Stripe activity, reviews, inventory use, accounting entries, tax evidence, media consent, search rankings, conversions, revenue, Cloudflare deployments, Production business data or R2 mutations.

Missing, contradictory or unobservable evidence remains a blocker, review state or unavailable state according to the owning authority. This build is schema-neutral, provider-neutral and observation-only.

## Build boundary

Build 395 may strengthen source checks, workflow composition, documentation and read-only release/runtime verification. It does not authorize database migration, Production business-data mutation, accounting posting, period close, customer charge/refund, provider mutation, DNS/secret changes, deployment mutation or destructive R2 work.
