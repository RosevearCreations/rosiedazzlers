# Build 925 — SCM/Task identity reconciliation and independently signed closure
This release adds a fail-closed evidence contract, not a live certification. SCM and Scheduled Task hosting are different and must be pinned separately for each component. A running task alone is insufficient: independently correlate its actual process, principal, executable digest and Authenticode status; otherwise return UNKNOWN and HOLD. No service changes or restarts are authorized.
 
The evaluator binds an original app attestation, host/boot, fresh case nonce, exact production SHA and two distinct original native receipt IDs. An independent inspector, in-person witness, two owners and independent production witness each require a distinct staff identity and Ed25519 pin; none may share the application signer. The physical witness binds the inspection digest, the production witness binds the deployed SHA, and both owners sign the digest of the entire evidence chain. Signatures must be fresh; test fixtures are never original evidence. A HOLD is not approval.
 
The caller must load the binding from private trusted custody, check original receiver receipts and freshness, independently enroll all public pins, verify provider deployment and smoke evidence, and enforce durable one-shot nonce consumption before operational closure. This module intentionally returns fieldCertified=false, sevenSourceConnected=false and authorizesAction=false even when closureReady=true. No browser-submitted pin roster or case is trusted. Build 924's API remains in place. The remaining work is original Windows task collector, private case admission/persistence and authorized on-site enrollment; until those exist, live field certification is HOLD.
 
Run node tests/build925_field_reconciliation.test.mjs on Node 24. The GitHub gate also runs Build 923 and 924 regressions.
