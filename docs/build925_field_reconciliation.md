## Original case and signature process
Collect fresh original 923 app attestation and both original 921 live native receipts. In Admin 925 issue a case using the app record ID. Case expires in 5 minutes; all evidence must be freshly collected. The API reloads durable originals and refuses stale or drifted configuration. Do not copy test evidence.
 
On each trusted Windows device use Node 24, Git checkout at the approved signer revision, and separate owner-only %LOCALAPPDATA% files. Set ROSEVEAR_ROSIE925_SIGNER_CONFIG_PATH, ROSEVEAR_ROSIE925_CASE_INPUT_PATH, ROSEVEAR_ROSIE925_PRIVATE_KEY_PATH. Config contains role, staffId, sourceCommit; inspector additionally windowsHostName, hostId, originalBootId, originalBootTimeMs from original 921/923 setup, identities mapping component to mode and identity. All input files use binding from issued case. Run node scripts/build925-sign-original-evidence.mjs for inspector. It reads CIM SCM process, or a single running scheduled task with one absolute executable action and a uniquely correlated child of its engine PID; checks actual process owner SID, hash, Authenticode and process stability. Ambiguous wrappers, user processes or unsigned binaries stay HOLD. No task or service is started.
 
For other roles run node scripts/build925-sign-original-evidence.mjs --confirm-my-original-review only after personal verification. Physical witness input: binding, inspector envelope, presence (IN_PERSON or NOT_PRESENT), observedRecovery boolean, decision (APPROVE or HOLD). Production witness input: binding, deploymentId, productionSha, canonicalSmoke (PASS/FAIL), providerStatus (SUCCESS/FAILURE) from actual provider review. Each owner input: binding, inspector, physical, production envelopes and decision (APPROVE/HOLD). The signatures bind the entire evidence chain, not just a checkbox. Submit JSON {caseId,inspector,physical,production,owners:[primary,second]} in Admin 925 as an enrolled owner. Case IDs and review digests cannot be replayed; owner HOLD is durable, not approval.
 
Even when closureReady=true the API records only signed original closure evidence; fieldCertified, sevenSourceConnected and authorizesAction remain false until independent operational authority explicitly closes the field gate. Do not simulate witnesses or imply that signed claims independently prove physical presence. Exact SHA deployment and canonical live smoke are required for software GREEN. No Windows restart is needed for the web release.
 
Run node tests/build925_field_reconciliation.test.mjs on Node 24. CI runs prior 923 and 924 regressions. The Windows collector requires testing on original hardware; hosted CI cannot certify it.
