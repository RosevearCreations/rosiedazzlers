## Case and admission

Sign in as the independently pinned custody authority at /admin-sysop-930.html. Refresh original receiver status and use the existing 928/921 read controls to obtain fresh genuine receiver-native witnesses. Issue a case only when the approved configuration and DB are ready. Each witness input is {binding,evidence}; authority input also includes guest and launcher envelopes. The authority signs a binding digest including both exact envelopes. Each signature expires within two minutes and the server case within five minutes. Submit {caseId,guest,launcher,authority}. The server rechecks fresh current native receiver witnesses and approved pins at admission. A changed receiver or case requires a fresh challenge; duplicate case, signature digest or prior receipt is rejected by the DB. A signed HOLD is a historical record, never approval.

First accepted receiver pair establishes a baseline; continuity requires a later pair with distinct new signed witnesses on the same pinned ledger/revision. A boot failure closes only on a later independently witnessed boot with correlated successful boot task/log and accepted guest and launcher evidence, after an approved signed previous failure under identical configuration. If the historical failure log is missing, it cannot be certified closed; investigate through the original Hub. A healthy recovery task alone is not boot success. No physical field certification, continuous health or seven-source CONNECTED is asserted. Source test success is separate from database installation and original evidence admission.
