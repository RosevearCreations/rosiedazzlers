## Signed original GitHub workflow-step ledger
Workflow `.github/workflows/rosie882-signed-enrollment-watch.yml` retains its every-2-hour schedule and explicit `workflow_dispatch`. Both original jobs preserve the Build 882 verification command, now with `continue-on-error: true`, followed by a guaranteed attempted Build 883 signed receipt append and a terminal step that **re-fails the job if original verification failed**. If signing/readback fails, the job fails. Missing independent signing material never creates a fake success. Job permissions are scoped to `contents:read`, `issues:write`, and exact repository/main checks.

`scripts/build883_execution_receipt.mjs` signs an exact canonical payload with the **same separately held GitHub Ed25519 private JWK already enrolled for Build 881/882**. Payload includes run ID/attempt, original workflow path, exact main SHA/ref, verified job mode (watch or anchor), schedule/manual event, timestamp, and `VERIFY_STEP_SUCCESS` or `VERIFY_STEP_HOLD`. The script writes the redacted, signed comment to the dedicated issue `[Rosie 883] Signed scheduler execution receipt ledger` and reads the exact comment back from the GitHub API, checking the signature and GitHub Actions bot author. It never serializes secrets, customer identifiers, financial records or original raw provider receipts. A step receipt is **not** an assertion that the whole GitHub workflow run has completed successfully, nor continuous scheduling uptime.

Issue comments can be modified/deleted by authorized GitHub actors; this is signed tamper-evident custody **not WORM or independent human witnessing**. Latest 100 entries are inspected; older records are explicitly out of bounded coverage. Duplicate run/mode/attempt pairs, invalid signatures, failed steps and stale entries stay HOLD.
