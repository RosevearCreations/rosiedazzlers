# Rosie Dazzlers Build 907 — Saved Smart Choices, Photo-to-Quote Continuity, Manual Basket & Account Recovery

## Smart Wizard: explicit saved selections
\`/book-smart\` offers Save / Restore / Clear. Stores *only generic choices* (size, goal, condition, concerns, selected optional service codes) in the customer's own browser, for **24 hours**. Save requires deliberate click. No name, email, address, vehicle identification, photos, upload proof, date, time slot, consent state, payment or quoted prices are saved. Restore is always rechecked against the current live catalogue and can never create a booking/hold or select a new add-on automatically. Existing Build 630 six-hour same-tab canonical planner draft remains independent and authoritative.

## Private photo-to-quote continuity
Prior upload signing was only an *intent* and a link in booking notes, not evidence bytes reached storage or staff received a linked file. Build 907 now:
1. Requires original same-origin POST, public feature flag \`PUBLIC_PHOTO_ESTIMATE_UPLOADS_ENABLED=true\`, real Supabase credentials and a successful original \`photo_estimate_uploads\` intent row. Returns a random 256-bit upload proof only to the current browser POST response and stores **SHA-256 digest only**.
2. After direct Storage PUT, the planner calls \`/api/public_photo_estimate_complete_v907\` with the original ephemeral receipt. Service-role authenticated **HEAD** checks the original storage object exists before the original row changes to \`uploaded\` with \`verified_at\`. A signed upload URL or browser-reported PUT without server confirmation is **not** considered uploaded.
3. An explicit, separate Step 5 **Request staff photo quote (no payment)** action submits private receipt IDs/proofs to \`/api/public_photo_quote_v907\`. That API rechecks current original status, 6-hour window, proof digest, unlinked status and item metadata; creates a real \`public_inquiry_leads\` record with idempotent \`client_request_id\`, then links original verified upload rows to the lead. Existing \`/api/admin/lead_quote_preview\` reads media by original \`lead_id\`. Shared HTTPS links may be included but are customer-supplied and not represented as verified uploads.
4. Partial linkage or stale/forged/expired receipts never report a complete attachment. Receipt proofs are never saved in browser storage, URLs, public quote notes, logs or staff API results. Private media remains **pending staff privacy review**. No automatic send, final quote, reservation or payment is created.
5. The original \`/api/checkout\` stays authoritative. It retains existing photo link and booking notes behavior. Choosing quote first does **not** charge deposit, occupy a booking slot or authorize photos for gallery/social.

The underlying Supabase original \`photo_estimate_uploads\` table was present with RLS. Additive migration \`20261117210000_build907_photo_quote_proof.sql\` adds two proof/verification columns, original intake uniqueness/lead lookup and idempotent quote request reference. Existing RLS remains; anon/authenticated database table privileges denied; service-role writes are internal only.

### Manual/Custom
\`/book-custom\` now shows category and text filters over the current add-on catalogue, explicit basket clearing, a separate quote-only selection group, and a no-payment staff-quote action. Quote-only and package-only choices never enter payable \`booking_mode:'ala_carte'\` codes. Existing owner-approved standalone prices, service-area/date availability, winter/site safety, deposit and Stripe/PayPal checkout checks remain authoritative.

### Forgotten-password/account end-to-end dry-run
Tests exercise the **real application code** against fake network/database/provider responses, not real users: opaque random token issuance, digest-only storage, successful one-time token consumption, credential update, revocation of all prior sessions and new HttpOnly cookie; duplicate token replay denied; unknown email generic; failed transactional provider delivery retires undelivered token; forgotten-sign-in-email request inserts into staff \`customer_account_recovery_requests\` with original privacy-safe response. Cross-origin and oversized reset/help requests are blocked. No actual customer reset, email or staff contact is created by tests. Staff queue already exists at \`/admin-customers\`.
