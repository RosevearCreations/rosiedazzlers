# Rosie Dazzlers 871 — Manual Quote Delivery Audit, Consent Withdrawal, Refund-Aware Original Deposit

## Staff workflow
1. Use existing camera-first Build 868–870 Admin Booking intake. Save private quote and separately obtain customer contact / quote-delivery permission. Issue an original 7-day link.
2. In **Customer Quote Delivery Audit**, select an active link, a manual channel (in-person, outside-app email/SMS, phone or other) and **staff-witnessed event**. Check the explicit attestation box and record. These entries are **staff assertions only**, not messaging-provider proof, send confirmations or marketing consent. Copying a link never auto-records delivery.
3. If customer withdraws quote-sharing permission, confirm actual customer withdrawal and link revocation, then click **Withdraw quote consent & revoke links**. The original database executes one locked transaction clearing name/email/phone in this draft, setting consent=false, and revoking all original v870 links. A trigger prevents the older Build 869 quick-quote editor silently regranting permission. A new intake and fresh consent is required; previous immutable events remain private.
4. Optional **stop future private photo capture** revokes the ability to sign new uploads for that draft. Already stored private media is not made public or silently purged; owner must review lawful retention and deletion requests separately. Existing ordinary booking/payment records are separate from quote-sharing withdrawal.
5. After the canonical booking is linked by the existing exact-email Build 869 function, click **Recheck current deposit & refunds**. The API performs a new, server-only Stripe or PayPal provider readback and appends an original-booking-scoped snapshot to the private audit. It never makes or refunds payments, changes booked totals or booking confirmation, or calls customer communications.

## Provider reconciliation contract
- Stripe: reuse the original canonical booking verification (session, metadata, CAD, exact payable amount), require stored payment intent equals the live Checkout session, fetch successful charge and all refunds for that payment intent from Stripe, reject missing/paginated/inconsistent evidence, pending refunds or mismatched refund totals. Report **intact**, **partial refund**, or **fully refunded** original deposit only from complete current evidence.
- PayPal: require live order to reference exact booking and contain original captured transaction, compare live capture amount/CAD to original deposit. `COMPLETED` verifies unrefunded capture; `REFUNDED` verifies full refund; `PARTIALLY_REFUNDED` causes a safe **HOLD** for the exact remaining amount rather than guessing.
- Gift-only/unsupported/unavailable providers: HOLD or explicit non-cash state, never count as verified net cash.
- A previous original deposit success is not a current refund balance, and no refund-aware snapshot is a paid-in-full invoice or unconditional appointment confirmation. Provider states can change later; recheck before a decision.
