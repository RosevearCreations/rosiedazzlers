# Build 405 — Full Responsive Production Acceptance & Roadmap Renewal

Build 405 is the capstone acceptance and consolidation release for the Build 396–405 phase. It does not create a parallel booking, payment, accounting, inventory, customer or deployment authority. It composes the retained authorities already proven in Development and Production, requires truthful evidence at every boundary, and renews the next roadmap from observed operational gaps rather than speculative feature accumulation.

## Critical-path acceptance matrix

The accepted customer-to-business path is:

1. **Visitor / public discovery** — responsive public routes, one meaningful H1 per indexable page, unique metadata/canonical/structured data, truthful Oxford/Norfolk service content and configured commercial/service authority.
2. **Booking / checkout** — responsive booking UX, authoritative package/add-on/vehicle/availability rules, retained recovery/idempotency safeguards and server-confirmed outcomes only.
3. **Customer account / retention** — exact customer-profile identity, explainable prior-service guidance, current catalog/condition/availability/scope/price reconfirmation and no inferred consent.
4. **Detailer field workflow** — responsive field surfaces, explicit loading/error/retry states, no idle polling and no silent business-state mutation.
5. **Operations / handoff** — manual/server-authoritative operational evidence, no invented ticket value, margin, payout, debt, forecast or customer score.
6. **Finance / payment / reconciliation** — retained payment-readiness, payment-evidence, reconciliation, close and accountant-export authorities remain fail-closed; pending or unavailable provider evidence never becomes accepted payment evidence.
7. **Production runtime** — exact GitHub SHA must match a successful Cloudflare Production deployment and pass immutable deployment smoke plus canonical `https://rosiedazzlers.ca` runtime/contextual smoke before Production is GREEN.

## Responsive acceptance rule

Representative **phone, tablet and desktop** support is mandatory across critical paths. Build 405 composes the retained responsive static/source authorities and exact Development/Production runtime HTTP acceptance. Static source checks must never be described as visual browser proof. If independent visual/browser evidence for a device class is unavailable, that evidence remains explicitly unavailable rather than being fabricated.

Responsive acceptance therefore requires all of the following:

- device-width viewport and no root-level oversized minimum-width blocker on public/app HTML surfaces;
- retained responsive UX authority for shared navigation, loading/error/empty/retry states and mobile/tablet guidance;
- retained booking/customer/Detailer/Operations/Finance source authorities;
- exact Development deployment/runtime acceptance before promotion;
- exact Production deployment/runtime/business acceptance after merge;
- any separately observed device-browser evidence to be additive evidence, never a substitute for server/runtime authority.

## Commercial and public consistency

Public discovery, specialty/add-on guidance, pricing/estimate language and booking handoff must remain consistent with configured catalog and server-authoritative booking/commercial rules. No static page may create a second price, eligibility, availability, package or add-on authority.

## Retained authority composition

Build 405 directly retains and re-runs the substantive authorities for:

- responsive/static UX and performance/accessibility/security;
- customer journey, booking quality, communication/self-service and booking recovery;

A retained authority failure is a Build 405 failure. Build 405 does not weaken an older gate merely to complete the capstone.

## Legacy continuity

Canonical public, booking, Customer, Detailer, Operations, Admin and Finance routes retain their compatibility/legacy route continuity where the retained route-copy and protected-route authorities require it. A renamed or consolidated surface does not silently strand a retained route.

## Mutation and evidence boundaries

Build 405 is source/acceptance/roadmap work only. It authorizes **no schema migration, Production business-data mutation, destructive R2 mutation, payment charge/refund, payment/provider mutation, accounting/inventory posting, customer mutation, automatic outreach, automatic booking, or hidden background replay queue**.

Provider-sensitive evidence remains fail-closed. External approvals, Stripe/PayPal live outcomes, Search Console/Google Business Profile proof, backup/export proof, or other provider evidence cannot be inferred from source code or a successful deployment.
