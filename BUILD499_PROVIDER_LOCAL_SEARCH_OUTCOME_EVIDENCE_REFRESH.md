# Build 499 — Provider & Local Search Outcome Evidence Refresh

## Purpose
Refresh the bounded provider-outcome and local-search evidence package from the retained authorities without contacting or mutating provider systems, and without turning descriptive movement into ranking, weather, demand or conversion causation.

## Provider outcomes & communications contract
The four retained provider evidence classes remain independent and provider-owned:
- Stripe payment outcome;
- PayPal payment outcome;
- linked definitive refund outcome; and
- definitive message-delivery outcome.

A provider row is current only when the expected evidence class is present, the retained provider source is available and attributable, the evidence timestamp is valid, freshness is current and the retained outcome is actually observed. Missing, stale, unavailable or unattributed provider evidence remains provider-dependent.

## Local-search outcome contract
Search Console and Google Business Profile evidence remains provider-owned and must come from the correct source identity:
- Search Console requires the correct property identity;
- Google Business Profile requires the correct location identity; and
- descriptive continuity requires distinct current/prior dated windows with equal calendar-day length.

First-party referral/funnel context remains a separate descriptive population. It is never substituted for Search Console/GBP evidence and is never joined to provider metrics, customers or persisted bookings.

## Southern Ontario truth boundary
Provider or referral movement does not prove ranking, indexing, Maps visibility, weather effects, winter demand, service availability, booking-conversion causation or any service working-temperature threshold. Cold-weather operability remains owned by the retained service/product/equipment/site evidence authorities.

## Mutation boundary
Read-only/manual refresh only. No payment, refund, message send, provider contact, Search Console/GBP write, automatic provider snapshot save, booking/quote mutation, customer outreach, content publishing, schema/storage mutation or permanent polling is authorized.

## Acceptance
The exact candidate must pass the focused Build 499 checker/test, retained Build 489 provider/local-search continuity, retained Build 480 local-search snapshot continuity, retained Build 476 provider traceability, Current Source Gate, exact feature-preview acceptance, exact-SHA Development deployment/runtime acceptance, protected-main governance and independent exact resulting-main Production deployment/runtime/business acceptance.

A GREEN Build 499 proves only that the application can truthfully classify whether the retained provider and local-search outcome evidence comes from the correct current attributable sources and comparable windows. It does not manufacture provider evidence or establish causal marketing performance.
