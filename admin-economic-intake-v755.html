ⓘ Evidence protocol & safety

How do we prepare an original source record?

Use the 13 exact fields documented in docs/build755_source_record_intake_owner_decision_audit.md. Hash the UTF-8 canonical transcript with SHA-256, then have the independent source witness use that digest as source_record_sha256 in the Build 754 signed attestation. Have the owner independently sign the SHA-256 of that exact witness transcript. The record must use the matching booking, period, before/after snapshots, correction reference and valid chronology.

What evidence can actually close an exception?

Not this screen. The original change must be independently retrieved and matched to the authoritative source's immutable history. A separately authorized owner must then record a decision in the owning source workflow. Neither the browser export nor its SHA-256 fingerprint is an immutable server audit or closure receipt.

What if a record is changed or an exception reappears?

Any hash, receipt, scope, source or chronology mismatch leaves the case on HOLD. A changed live source requires a new current retest and fresh independent signatures. No automatic price, stock, cost, wage, accounting, booking, seasonal, outreach or provider changes are permitted.
