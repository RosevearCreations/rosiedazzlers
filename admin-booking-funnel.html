Measurement contract
  • Read-only analytics; no booking, customer or payment mutation.
  • Counts unique sessions reaching each stage, not repeated clicks or page refreshes.

  • No background polling; evidence refreshes only when requested.

Operating Help

Why use unique sessions?

A customer can revisit a step or refresh a page. Counting each event would inflate activity. Build 324 counts whether a session reached a stage at least once.

What do the five stages mean?

Step 1 is date and vehicle, Step 2 package selection, Step 3 add-ons, Step 4 customer details, and Step 5 deposit/payment handoff. Checkout start and completion are shown after those wizard stages.

How should mobile vs desktop be interpreted?

The dashboard compares start-to-completion rates. A gap larger than five percentage points is surfaced as a meaningful directional signal, but small sample sizes should be treated cautiously.

Why is the window capped at 30 days?

This view intentionally queries a bounded raw-event window so device-by-funnel analysis does not recreate the earlier high-CPU analytics problem. The normal Analytics page continues using compact rollups for longer windows.

Does this track new personal information?

No. It aggregates the existing session ID, device classification and booking event names already stored by the analytics system and returns only counts and rates.
