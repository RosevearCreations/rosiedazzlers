Where each kind of value belongs

Encrypted secret

Tokens, passwords, service-role keys and webhook signing secrets belong in the Development/Production server environment that consumes them.

Environment variable

Non-secret IDs and public configuration may be environment variables when the registry says so. Public does not mean “paste everywhere.”

Cloudflare binding

R2 access is a Pages binding to a bucket. It is not an API token field and should not be copied into Supabase or site settings.

Application setting

Some operational provider rules and public push configuration live in Rosie's database-backed settings. The I.T. card identifies these exceptions.

External control plane

GitHub and some provider ownership tools can be valid integrations without a Rosie runtime credential. Do not invent a key unless an approved adapter requires one.

Security boundary: never paste API secrets, passwords, service-role keys, access tokens or webhook secrets into Site Settings, Social Queue notes, Markdown, GitHub source, browser JavaScript or diagnostic evidence. This page reports presence only.

Safe connection test standard

  1. Use the Development environment and the provider's sandbox/test mode where one exists.
  2. Confirm the exact variable/binding names on this page before adding anything.
  3. Open the circled i and complete its provider-specific acquisition, scope, callback and storage steps.
  4. Test one bounded integration at a time with non-customer test data.
  5. Verify both configuration presence and the provider-side result; presence alone is not acceptance.
  6. Record only pass/fail evidence and safe identifiers. Never paste a secret or customer-private payload into test notes.

DAIP boundary remains held

The I.T. catalogue does not authorize DAIP storage, uploads, processing, AI, public exports or publishing. Gate C remains held until its independent acceptance boundary is satisfied.
