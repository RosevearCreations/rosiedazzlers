Operating Help

What does Stripe test-ready mean?

The server can see a Stripe secret whose prefix identifies it as a test key. The key itself is never returned to the browser. Test-ready does not create a charge; it only confirms that Development has test-mode credentials available for the existing explicit checkout workflow.

What if a live Stripe key is detected?

Development readiness is blocked. Do not use live charging credentials for Development acceptance. Correct the server-side environment configuration before exercising provider tests.

Why does PayPal show not integrated?

The current application source does not contain a PayPal checkout integration. Build 318 reports that honestly rather than inventing configuration. PayPal sandbox acceptance remains unavailable until a deliberate integration is implemented.

What is manual fallback?

The existing final-balance workflow can fall back to an operator-managed payment handoff when Stripe is unavailable. Recording payment remains a deliberate staff action; this readiness screen never records money.

Where do I verify actual Development evidence?

Open Acceptance Evidence after readiness. It reports persisted checkout and paid-state evidence separately, remains read-only, and does not claim webhook verification without an authoritative source.

Where do I actually request payment?

Use Final Balance Readiness. That workflow requires explicit operator actions and confirmations. This page is read-only and exists only to show whether the provider layer is safe for Development testing.
