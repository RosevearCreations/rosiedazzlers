# Build 564 — Atomic Ledger Adapter and Provider Credential Readiness
Adds an actual Supabase REST RPC adapter using server-held service-role credentials, with an atomic Postgres INSERT ON CONFLICT function, idempotent replay confirmation, and a fail-closed environment configuration inspector. Provider credentials must be provisioned as Cloudflare server secrets and may not be committed to GitHub. Required names: DAIP_WORKER_IDENTITY_PROVIDER_URL, DAIP_WORKER_IDENTITY_PROVIDER_TOKEN, DAIP_CONSENT_PROVIDER_URL, DAIP_CONSENT_PROVIDER_TOKEN, DAIP_LEDGER_AUTHORITY_REFERENCE, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY.
**Caution:** Provider API formats are not established and no actual worker or consent provider has been bound. Do not treat configuration presence as verification. The SQL depends on the unexecuted Build 562 migration and is not run automatically. The idempotent adapter is not wired into a live request route until trusted provider adapters exist. The legacy Build 563 adapter interface additionally needs a real server-computed evidence_digest; missing digest must remain HOLD.
**Runtime acceptance:** Verify real providers and registered keys, approved migration, duplicate replay, revoked-consent rejection, exact Cloudflare deployment SHA, and independent authenticated operator checks before release. This build reports no live acceptance or publishing.
