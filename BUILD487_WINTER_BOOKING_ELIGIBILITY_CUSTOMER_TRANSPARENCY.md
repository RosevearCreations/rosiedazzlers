# Build 487 — Winter Booking Eligibility & Customer Transparency

## Purpose
Prepare evidence-backed winter booking/quote eligibility states and customer limitation wording from the retained Build 486 capability matrix. This release does not create a second weather rules engine and does not publish or enforce a broad winter-service claim.

## Eligibility preparation
- `cold-snap-capable` becomes conditional winter consideration; current site/weather confirmation is still required.
- `temperature-limited-outdoor` requires a weather-condition check against source-owned limits when an exact limit is recorded.
- `controlled-environment-required` requires a suitable controlled environment; outdoor winter execution is not assumed.

Prepared customer wording remains draft and requires owner review. It is not automatically published, sent or inserted into a booking.

## Conversion interpretation
Explicitly weather-ineligible sessions are excluded from ordinary conversion interpretation. A cold-weather restriction is not a booking/quote conversion failure. If attributable session-level weather eligibility evidence is missing, Build 487 does not invent an adjusted conversion rate.

## Truth boundary
Capability evidence is not blanket availability. A forecast does not create service capability. Missing working-temperature limits remain missing. Prepared wording is not a public claim.

## Mutation boundary
Read-only and manual refresh only. No automatic booking/availability change, quote eligibility mutation, public winter claim, customer message, price/discount change, provider action, accounting/inventory mutation, schema/storage mutation, outreach or permanent polling is authorized.

## Acceptance
The exact candidate must pass the focused Build 487 checker/test, retained Build 486/483 seasonal authorities, retained booking conversion truth boundaries, Current Source Gate, exact feature-preview acceptance, exact-SHA Development deployment/runtime acceptance, protected-main governance and independent exact resulting-main Production deployment/runtime/business acceptance.
